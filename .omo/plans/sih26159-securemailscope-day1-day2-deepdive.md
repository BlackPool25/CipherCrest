# sih26159-securemailscope-day1-day2-deepdive - Work Plan

## TL;DR (For humans)

**What you'll get:** By end of Day 2 you have a frozen shared contract (`shared/schemas.py` + `schemas.json`) that 6 agents import, three tshark-golden fixture families (587 upgrade / 993 TLS1.3 opaque / stripped cleartext) with `manifest.json`, a triple-smoke Docker lab (`postfix:3.9` + `dovecot:2.3` + certs), a `POST /analyze` stub that returns validated `list[FlowVerdict]` from fixtures, and a Vite React dashboard gauge + 23-col threat matrix shell reading those fixtures — all under a server-side CI hard-fail gate.

**Why this approach:** Full 6-model freeze Day1 (not incremental) removes re-wire churn; tshark with `tcp.reassemble_out_of_order:true` + `tls.desegment_ssl_records:true` is the only honest oracle (both OFF by default since 3.0) so fixtures are real-grounded from smoke pcaps, not hand-mocks; triple smoke (01+06+09) exercises STARTTLS vs implicit vs opaque branches Day1; wheelhouse deferred to Day2/5 keeps Day1 under 5h.

**What it will NOT do:** No real X.509 chain validation logic, no ML/Risk/Anomaly, no Policy/Quarantine/SIEM, no weberblog/limbo ingestion, no `pip download` wheelhouse or `docker save` bundle on Day1 — those are Day3-5. No live capture needing `NET_RAW`; replay is primary.

**Effort:** Medium (2 days, ~10-12h wall, 4 agents parallel)
**Risk:** Medium — Day1 gate is tshark parity + schema 20/20; if tshark prefs wrong, fixtures silently diverge. Mitigated by `reassemble_out_of_order:true` + `desegment_ssl_records:true` citation and parity test.
